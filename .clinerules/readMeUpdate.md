# README updates (only when users or teammates are affected)

Update a README only when the change affects someone using or running the project. Never rewrite a README for a small patch.

## Update the README when you
- add or change a feature, a screen or an endpoint
- change install steps, scripts or environment variables
- change the architecture, the file layout or a project rule
- make a breaking change

## Do not update the README for
bug fixes, refactors, tests, styling or silent performance work.

## Where
- Screens and the UI: `frontend/README.md`
- Endpoints and the API: `backend/README.md`
- Tables and SQL files: `DataBase/README.md` (list every new SQL file in the order it must be run)
- Keep the existing headings and tone. Change only the section that is affected.
